# 作业提交助手

微信小程序前端已经写好，**后端 Python 部分留给你自己实现**。这份文档说明：前端怎么跑、后端要提供什么接口、命名规则、以及建议的学习顺序。

## 一、整体流程

```
主页选科目 → 拍照（可旋转/排序/删除/重拍）→ 点“生成 PDF”
   │
   ├─ 逐页上传图片 ──────────────> Python：保存图片
   └─ 请求生成（科目、编号、姓名、学号、旋转角度、是否增强）
                                   Python：旋转 → 裁边/摆正/增强 → 合成 PDF → 按科目规则命名
手机 <──── 文件名 + 下载地址 ───── Python
手机：预览 / 发送给老师（成功后该科目“下次编号”自动 +1）
```

**前端负责**：保存姓名学号（只填一次）、四个固定科目、编号自动 +1、拍照、旋转/排序/删除/重拍、上传、下载、分享。
**后端负责**：收图片、图像处理、合成 PDF、**命名**、提供下载。

### 关于“姓名学号绑定微信账号”

微信**不会**把用户的真实姓名和学号提供给小程序，所以首次必须自己填一次。填写后保存在这个微信账号在本机的小程序存储里，之后不用再输入；但换手机、卸载或清除小程序数据后需要重填。
想做到“换设备也自动带出”，要把信息存在你的服务器上，并用微信的 `openid` 区分用户，见下面的“阶段 8（选做）”。

## 二、前端怎么运行

1. 微信开发者工具里「项目 → 导入项目」，选本文件夹（含 `app.json` 的那一层），AppID 选测试号。
2. 「详情 → 本地设置」勾选「不校验合法域名……」。
3. 后端地址在 `utils/config.js` 的 `BASE_URL`，默认 `http://127.0.0.1:5000`。
4. 真机预览：把 `BASE_URL` 改成电脑的局域网 IP（如 `http://192.168.1.23:5000`），手机和电脑连同一个 Wi-Fi，并在手机上打开「调试」。
5. 正式发布需要 https 域名并在小程序后台配置，是最后阶段的事。

## 三、前端文件说明

| 文件 | 作用 |
|---|---|
| `pages/home/` | 主页：四个科目入口，显示每个科目“下次编号” |
| `pages/submit/` | 提交页：编号（上下滑动或手动输入，1~17）、拍照、图片编辑、生成与导出 |
| `pages/profile/` | 姓名学号（只填一次） |
| `utils/subjects.js` | 四个科目的配置（编号上限 17）与“下次编号”的存取 |
| `utils/api.js` | 与后端通信（上传、生成、下载） |
| `utils/config.js` | 后端地址 |

## 四、你要实现的接口

成功：`{"ok": true, ...}`；失败：HTTP 400/500 加 `{"ok": false, "message": "给用户看的原因"}`。

### 1. `GET /api/ping`
返回 `{"ok": true}`，用来测试服务是否启动。

### 2. `POST /api/upload`（multipart/form-data）

| 字段 | 说明 |
|---|---|
| `file` | 一页图片 |
| `task_id` | 一次生成任务的编号，形如 `1730624880123_ab12cd` |
| `index` | 页码，从 0 开始（前端已按用户排好的顺序上传） |

返回 `{"ok": true}`。

### 3. `POST /api/make_pdf`（JSON）

```json
{
  "task_id": "1730624880123_ab12cd",
  "subject": "数学分析",
  "number": 3,
  "name": "张三",
  "student_id": "2026001234",
  "rotations": [0, 90, 0],
  "enhance": true
}
```

- `subject`：`数学分析` / `高等代数` / `微观经济学` / `会计学原理` 之一，其他值返回 400。
- `number`：编号 X（周数、Lecture 序号或章数），整数，范围 1~17。后端要检查：不是整数或超出范围就返回 400。
- `rotations`：与页码一一对应，**顺时针**角度，取值 0/90/180/270。
- `enhance`：`true` 时做裁边、摆正、增强；`false` 时只旋转并原样放进 PDF。

成功返回：
```json
{
  "ok": true,
  "filename": "张三 2026001234 第3周.pdf",
  "url": "/files/xxxx.pdf",
  "warnings": ["第2页没有检测到纸张边缘，已保留原图"]
}
```
`warnings` 可以没有或为空数组，前端有就会显示给用户。

### 4. `GET /files/<文件>`
返回 PDF 内容。

## 五、命名规则（后端生成，用户不输入）

示例里 X=3，姓名“张三”，学号“2026001234”：

| 科目 | 规则 | 结果 |
|---|---|---|
| 数学分析 | `姓名 学号 第X周` | `张三 2026001234 第3周.pdf` |
| 高等代数 | `LectureX作业 学号 姓名` | `Lecture3作业 2026001234 张三.pdf` |
| 微观经济学 | `第X章微观经济学` | `第3章微观经济学.pdf` |
| 会计学原理 | `第X周 姓名 学号` | `第3周 张三 2026001234.pdf` |

提示：用字典把“科目 → 格式模板”存起来，再用字符串格式化，比写四段 `if` 好得多，以后加科目也只改字典。姓名里如果混入非法文件名字符（`\ / : * ? " < > |`）要清理。

## 六、分阶段任务

### 阶段 1：让服务跑起来
- 学：虚拟环境 `venv`、`pip`、Flask 路由、返回 JSON。
- 做：`/api/ping`。
- 验收：浏览器能打开并看到 `{"ok": true}`。

### 阶段 2：接收并保存图片
- 学：`request.files` / `request.form`、`pathlib` 处理路径、文件读写。
- 做：`/api/upload`，每个 `task_id` 一个文件夹，按页码保存。
- 验收：`curl -F "file=@test.jpg" -F "task_id=t1" -F "index=0" http://127.0.0.1:5000/api/upload`，文件夹里出现图片。
- **安全**：`task_id` 来自用户，直接拼进路径会被 `../` 跳出目录。只允许字母、数字、下划线。

### 阶段 3：不增强的 PDF（先打通主链路）
- 学：`Pillow`（`pip install pillow`）、列表排序、`try/except`。
- 做：按页码把图片合成多页 PDF，并应用 `rotations`。
- 要点：
  - 手机照片常带方向信息：先用 `ImageOps.exif_transpose`，再应用用户的旋转。
  - Pillow 的 `rotate` 是**逆时针**，而 `rotations` 是顺时针，注意符号（或用 `transpose`）。
  - 转成 RGB 再保存 PDF。
  - 页码按**数字**排序，别用字符串排序（`10` 会排到 `2` 前面）。
- 验收：写个独立小脚本，不经过 Flask，先把几张图合成 PDF 并能正常打开。

### 阶段 4：自动命名
- 学：字典、f-string 或 `str.format`、字符串清理。
- 做：按第五节的规则，写一个函数：输入科目、编号、姓名、学号，输出文件名。
- 验收：四个科目各测一次；传入不认识的科目要报错；给姓名里塞入 `/` 之类的字符，结果仍是合法文件名。

### 阶段 5：接口串联
- 做：`/api/make_pdf` 与 `/files/<文件>`。缺字段、`task_id` 不存在、没有图片等情况，都返回清晰的 `message`。
- 提示：磁盘上用唯一文件名保存，真正的名字只放进 JSON 的 `filename`，避免同名覆盖和路径问题。
- 验收：小程序完整走通一遍，能预览和发送。

### 阶段 6：扫描增强（裁桌面、摆正、增强文字）
- 学：`OpenCV`（`pip install opencv-python numpy`）。
- 思路（每步都可以单独写个脚本验证，画出结果看一看）：
  1. 缩小一份到较小尺寸（比如高度 800~1000 像素）用于检测，节省时间。
  2. 灰度 → 高斯模糊 → `Canny` 边缘 → 膨胀，把断开的边缘连上。
  3. `findContours` 找轮廓，按面积从大到小排，用 `approxPolyDP` 找第一个近似四边形的。
  4. 把四个角点按“左上、右上、右下、左下”排好序，并还原到原图坐标。
  5. `getPerspectiveTransform` + `warpPerspective`，得到端正的纸张（这一步同时完成了“裁掉桌面”和“拉正”）。
  6. 增强文字：先试 `adaptiveThreshold`（黑白扫描效果）；也可以试“用大核模糊估计背景再相除”，去阴影同时保留灰度。
- 失败兜底：找不到合理的四边形时（例如面积太小、拍得太近），**保留原图**，并往响应的 `warnings` 里加一句提示，让用户知道哪一页没处理。
- 取舍：纯黑白阈值会损失铅笔字和彩色笔迹，可以做个对比，决定默认用哪种。
- 验收：准备几组测试照片（斜着拍、背景杂乱、光线不均、纸占满画面），观察效果，记下哪些情况会失败。

### 阶段 7（选做）：清理
- 定时删除过期的图片和 PDF。

### 阶段 8（选做）：姓名学号绑定微信账号
- 前端调用 `wx.login` 拿 `code`，发给后端；后端用 `code2session` 接口换 `openid`（需要 AppID 和 AppSecret，测试号也有）。
- 后端用 `openid` 存取姓名学号（先用 JSON 文件，再换 SQLite），前端启动时拉取。
- 这是一个很好的练习：HTTP 请求（`requests` 库）、文件或数据库读写、密钥不要写进代码里。

### 阶段 9（选做）：部署
- 云服务器 + https 域名，并在小程序后台配置合法域名。

## 七、给学过 C 的你的 Python 对照

- 没有分号和花括号，靠缩进划分代码块。
- 变量不用声明类型；列表（list）≈ 可变长数组；字典（dict）≈ 键值对，JSON 就是它。
- 内存不用手动管理，但文件用完要关：养成 `with open(...) as f:` 的习惯。
- 错误用 `try/except` 处理，而不是检查返回值。
